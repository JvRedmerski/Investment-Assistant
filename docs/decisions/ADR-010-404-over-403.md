# ADR-010 — 404 em vez de 403 para recurso de outro usuário

## Status

Accepted (2026-08-16, Wave 04)

## Context

Ao acessar uma carteira que existe mas pertence a outro usuário, um 403 confirma que aquele ID existe. Iterando IDs, um atacante mapeia quantas carteiras existem no sistema e quais IDs são válidos.

## Decision

Recursos escopados por usuário são resolvidos por `(id, user_id)` em uma única query. Se nada retorna — não existe **ou** é de outro dono — a resposta é **404** com o mesmo corpo nos dois casos. Nunca 403.

## Evidence

- `backend/app/api/routes/portfolios.py` — `_get_owned_portfolio`, com docstring explicando exatamente esse raciocínio; filtra por `Portfolio.id == portfolio_id, Portfolio.user_id == user.id`.
- `backend/tests/test_portfolios.py` e `test_transactions.py` — casos de isolamento entre usuários verificando o 404.

## Alternatives

- 403 Forbidden — semanticamente mais preciso, mas vaza existência.
- 404 apenas para inexistente e 403 para alheio — a pior combinação: vaza exatamente a informação que se quer esconder.

## Consequences

- ✅ Não é possível enumerar IDs de outros usuários.
- ✅ Um único helper por recurso concentra a checagem de ownership — difícil esquecer.
- ⚠️ Menos preciso semanticamente; a mensagem de erro não ajuda a depurar um bug de permissão. Aceito conscientemente.
- ⚠️ **Aplique o mesmo padrão a todo recurso escopado por usuário** (snapshots, recomendações, resultados de paper trading). Note que `assets` é um catálogo global, não escopado — 404 lá significa apenas "não cadastrado".
